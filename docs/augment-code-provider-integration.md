# Augment Code browser session and credits

The iPhone add/reauthorize flow opens an account-owned ephemeral WebKit container at `https://app.augmentcode.com/`. Only `_session` (required) and `web_rpc_proxy_session` (optional) from the exact app host or Augment parent domain, valid for `/api/credits` and not expired, become the restricted Cookie header. The common WebProviderSession binds provider, origin, local UUID and actual cookie values, and rejects altered/mismatched credentials before networking. No Safari, CLI folder, editor Keychain or real credential is read during implementation.

Both devices use `GET https://app.augmentcode.com/api/credits` with Cookie and JSON Accept. The optional `/api/subscription` request supplies planName and the declared billingPeriodEnd; errors there keep the successful credits with unknown plan/reset. Cancellation remains cancellation, rather than partial success. Redirects are refused, automatic Cookie handling disabled and cached responses are not given fresh collection times. Credentials persist through the existing Keychain/configuration/iCloud lifecycle; multiple accounts remain UUID-isolated, local mode works without cloud and Watch queries directly after credentials arrive.

The contract is pinned to [Pulse397c8fc4](https://github.com/qunqin24/Pulse/blob/397c8fc4f1bd52180a452d2f3f0c099def97cf69/Sources/Pulse/Providers/Profiled/AugmentUsageService.swift), its [provider notes](https://github.com/qunqin24/Pulse/blob/397c8fc4f1bd52180a452d2f3f0c099def97cf69/Docs/providers/augment.md) and fixtures. The official public `augmentcode/auggie` repository was inspected; it does not expose an authoritative personal-console denominator definition. Pulse itself calls the cookie and available semantics second-hand/unverified.

Accordingly `usageUnitsConsumedThisBillingCycle` and `usageUnitsRemaining` are retained as independent exact Decimal counts. `usageUnitsAvailable` is not promoted to a total just because of its name, and used+remaining is not invented as a reported allowance. There is no fake percentage, exhausted flag, wallet or monetary currency. At least one reliable reported counter is required; missing remains unknown, Boolean/negative/nonfinite/bad JSON or HTML fails and preserves old data. Card, detail, Watch and widget use the same counters; without a denominator the summary shows both available reported used/remaining amounts rather than hiding one.

The static quotaStatusText explains that the total is unconfirmed. It does not hide numeric windows. No percentage/low-wallet alert is offered without a basis. When the service states a valid billingPeriodEnd and actual consumed credits exist, the existing planner can schedule an expected reset from that timestamp; no date is inferred from “monthly”. The account controls expose the reset toggle only with an actual reported date. Demo data uses isolated local stores and the same partial-count semantics.

Original paths/viewBox remain; explicit 16x16 dimensions and vector/template asset settings were added. Full notice is in ProviderIconNotices.txt.

Six regression methods cover extraction/expiry/UUID/origin, two routes and optional failure, no invented denominator, invalid values/HTML/tampering, reset vs quota alerts, widget/coding/demo and account restore/rekey/delete/failure isolation. New source/tests and PBX passed syntax/plist checks; root owns the aggregate compiler/XCTest run. No Xcode/simulator was started by this worker.

Current user acceptance is implemented integration plus icon presence; true account/device validation is not a close condition. The exact live Cookie names/available meaning, anti-bot/login behavior, session expiry and Watch reuse remain observationally unverified and are not presented as measured facts.
