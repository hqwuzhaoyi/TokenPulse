# 各提供商额度展示与通知设计

本文记录 TokenPulse 截至 2026-09-09 的当前实现，用于核对各提供商的额度展示和通知是否符合产品预期。这里描述的是代码现状，不把尚未完成的真机验证视为已验收。

## 统一模型

提供商解析器只负责把远端响应转换为额度窗口；额度策略再根据提供商、套餐和使用场景选择窗口。两层职责不混用：

- 额度周期：`5 小时`、`每周`、`每月`、`其他`。周期来自提供商的时长或明确字段，不依赖中文展示名称。
- 额度范围：`账号级额度`没有模型范围；`辅助额度`带有模型或功能范围。
- 使用场景：`概览`、`详情`、`小组件`、`通知`。
- 缺失指标：显示“未提供”，不补成 0，也不猜测不存在的窗口。
- 无限额度：可以展示为“无限”，不触发额度告警，也不预排重置提醒。

## 通知通用规则

### 额度告警

- iPhone 应用级通知总开关默认关闭；Apple Watch 首次启动自动请求系统通知权限，用户允许后 Watch 端默认开启。系统拒绝状态不能由应用绕过。
- 每个订阅账号的额度告警默认开启，默认阈值为 80%、95%、100%。
- 首次成功刷新时，如果已超过阈值，也会提醒；一次跨过多个阈值时只展示最高档，并记录低档已提醒。
- 同一额度窗口、同一周期、同一阈值只提醒一次；进入新周期后重新允许提醒。
- 同一账号一次刷新触发多个窗口时合并为一条通知。
- iPhone 和 Watch 独立判断；同步后的提醒账本会减少重复，离线期间仍可能分别提醒。
- 请求失败、读取缓存或仅到达预计重置时间不会制造新的额度告警。

### 重置提醒

- 订阅账号的重置提醒默认开启，但仍受应用级通知总开关控制。
- 只有非无限、已用比例明确且大于 0、重置时间晚于当前时间的可通知窗口才预排“预计已重置”。
- 最新快照改变重置时间、套餐或窗口策略时，会替换计划并取消不再适用的待投递通知。
- 查询确认周期已经变化时，可以发送“额度已确认重置”；已经为同一次重置发送过预计提醒时不重复确认。
- 没有明确重置时间时不预排；只有提供商返回可识别的新周期后才可能确认重置。

## 各提供商详细设计

### Claude

数据来源为 Claude Web 会话接口。新版响应中的 `session` 映射为 5 小时额度，`weekly_all` 和 `weekly_scoped` 映射为每周额度；旧响应兼容 `five_hour` 和 `seven_day`。

- 无模型范围的窗口是账号级额度；`weekly_scoped` 的模型名称保留为范围。Fable 使用服务端 `scope.model.display_name`，不存在时不制造占位。
- 概览、详情、小组件和通知当前都使用所有返回窗口；标题显示为“Fable 每周额度”等带范围名称。
- 主屏幕小/中/大组件可显示 5 小时、账号每周、Fable 每周三个环；Inline 可列出三个值，角落、圆形和矩形附件受空间限制仍显示主窗口。
- 小组件展示重置时间。
- 当前没有 Claude 套餐名称识别。
- 会话 Cookie、组织选择、真实响应变化仍待实机验证。

### Codex Plus

数据来源为 `GET https://chatgpt.com/backend-api/wham/usage`。根级 `rate_limit` 视为账号级额度，`plan_type=plus` 识别为 Plus。

- 账号级 5 小时和每周窗口进入概览、详情、小组件及通知；详情同时显示套餐和剩余可手动重置次数。
- 如果 Plus 响应也带辅助额度，详情为每个范围保留首个简洁字段，辅助额度不进入其他场景。
- 额度告警分别按两个窗口判断；同次触发时合并通知。
- 两个窗口只有在已有实际用量时才安排各自的重置提醒。
- 当前没有真实 Plus 账号响应证据，窗口组合依据合成契约测试和参考实现。

### Codex Pro

同样读取 `/wham/usage`，`plan_type=pro` 识别为 Pro。当前已核对的真实脱敏响应为：账号级 `primary_window` 是每周额度，`secondary_window` 为空；`additional_rate_limits` 中另有 GPT-5.3-Codex-Spark 的 5 小时和每周窗口。

- 概览和小组件只显示账号级每周额度。
- 详情显示套餐 `Pro`、账号级每周额度、Spark 的首个额度窗口作为一个简洁字段，以及剩余可手动重置次数。
- Spark 不参与额度告警、预计重置提醒或确认重置提醒。
- Pro 即使收到账号级 5 小时窗口，也会由额度策略排除。
- Plus / Pro 切换时，窗口身份包含标准周期，不能把 5 小时槽位变化误判为每周额度已经重置。
- `/wham/usage` 是私有接口；套餐或字段缺失时保持“未提供”。

### OpenCode Go

数据来源为 `GET https://opencode.ai/zen/go/v1/usage`，使用用户录入并由 Keychain 保护的 OpenCode Go API Key。移动端不读取 Mac 的 OpenCode 配置或本地会话。

- `usage.rolling`、`usage.weekly`、`usage.monthly` 分别归一为 5 小时、每周、每月额度。
- 概览、详情和通知使用所有带有效已用百分比的窗口；主屏幕小/中/大组件显示三个环，Inline 列出三个值，角落、圆形和矩形附件显示主窗口。
- `percent` 是已用百分比；`status=rate-limited` 显示为“已用尽”，额度告警按 100% 档处理。
- 只有有实际用量并带未来 `resetsAt` 的窗口才预排重置提醒。
- HTTP 401 表示 Key 无效；HTTP 403 表示账号没有 OpenCode Go 套餐；两者使用不同错误提示。
- 响应不含套餐名和 Zen 余额。产品固定标识为 OpenCode Go，不推断余额或其他 OpenCode provider 用量。
- 路由有 OpenCode 第一方服务端源码证据，但未列入公开 endpoint 文档，仍需真实 Key 和双端验证。

### Z.ai / GLM

数据来源为国际版 Coding Plan 额度接口。`TOKENS_LIMIT`、`CREDIT_LIMIT` 和 `TIME_LIMIT` 根据 `unit + number` 换算周期；`TIME_LIMIT` 的特定组合当前映射为一个月并标记范围 `MCP`。

- App 和 Watch 概览、详情当前展示全部返回窗口。
- 通知也处理全部返回窗口，因此 `MCP` 月额度可能触发额度告警和重置提醒。
- 小组件只展示无范围的每周和 5 小时额度，不展示 `MCP` 月额度。
- 当前没有套餐名称识别。

### MiniMax 国内版

数据来源为国内版 Coding Plan `model_remains`。每个模型可能返回短周期和每周窗口；`model_name=general` 视为账号级，其余名称保留为模型范围。

- 起止时间相差 5 小时时，短周期归一为 5 小时；缺失可靠起止时间时保留为“其他”周期。
- App 和 Watch 概览、详情展示全部返回窗口。
- 通知处理全部返回窗口；无限窗口不提醒。
- iPhone 主屏幕、锁屏、表盘和智能叠放组件统一展示 5 小时额度，优先选择无范围窗口；没有无范围窗口时按组件容量展示模型级 5 小时额度。
- 每个额度环显示自己的重置时间；没有可靠时间时明确显示“未提供”。
- 当同一模型的短周期和周额度都明确为无配额时，该模型不生成额度窗口。

### SuperGrok

数据来源为 CLI billing proxy；响应缺少用量百分比时，再尝试只读 credits RPC。当前把 billing `config` 表示为一个账号级共享套餐窗口。

- App 和 Watch 概览、详情只显示这个共享池。
- 小组件固定把该共享池标为“每周已用”并展示重置时间。
- 只有拿到明确百分比时才可能触发额度告警或预排重置提醒；缺失值不按 0 处理。
- 当前没有套餐名称识别，也没有已核实的手动重置次数。
- 小组件把可手动重置次数作为账号级信息显示一次。当前公开实现与已核实响应只提供用量、周期和预付余额，没有可信的剩余手动重置次数字段，因此显示“未提供”，不使用原型示意值。

## 待确认项

请重点确认以下产品决策：

1. Claude 的 Fable 模型级周额度已进入概览、详情和主屏幕小组件；是否继续参与额度告警和重置提醒。
2. Z.ai 的 `MCP` 月额度是否应该参与通知，以及是否需要进入大尺寸小组件。
3. MiniMax 的模型级窗口是否全部参与通知，还是只通知 `general` 账号级窗口。
4. SuperGrok 是否应固定解释为每周额度；若周期无法识别，是否应改为“套餐额度”。
5. 未识别套餐或新增提供商是否继续采用“所有返回窗口均展示并通知”的默认策略。

## 验证边界

- 自动测试当前覆盖 87 项，包括窗口解析、统一额度策略、Plus / Pro 展示差异、OpenCode Go 三周期与错误语义、Claude Fable scoped 窗口与通知名称、Widget 账号容量、Watch 表盘账号选择、环形未知状态与账号级重置次数、Spark 通知排除、套餐切换和重置提醒条件。
- MiniMax 和 GLM 有用户反馈的真实查询成功证据。
- Codex Pro 已通过本机登录账号核对脱敏额度结构，但移动端设备码登录、凭证轮换和双端行为仍未完成完整实机验收。
- OpenCode Go 已用原 Pulse 与 OpenCode 第一方源码核对接口，但尚无真实 Key 实机结果。
- Claude 与 SuperGrok 仍只有自动测试和参考契约，不能视为真实订阅验收完成。
