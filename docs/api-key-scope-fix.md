# Legacy API Key envelope scope repair

An offline probe from root `23e396c` used the actual `QuotaMonitor`, `ProviderCredentialEnvelope` codec and source-identity getter, production account models, synthetic DeepSeek Keys, and in-memory stores/query results. Key A succeeded; Key B replaced it and its query failed. Before the fix both old cache retention and later old cloud snapshot acceptance were true, and the probe exited 1. After the getter fix, the same probe prints `old_cache_after_key_change_failure=false; old_cloud_accepted=false` and exits 0. A second run with forged old fingerprint metadata and an unrelated `webSessionFormat=v1` also passes. No Keychain credential, real provider request, simulator or Xcode was used.

Cause: the default getter relied on optional/claimed fingerprint metadata. Legacy DeepSeek/Poe/ElevenLabs envelopes without it had no identity, so the existing monitor's binding and synchronized-snapshot guards were bypassed. A copied old fingerprint could also keep a changed Key in an old identity.

The default envelope API Key branch now derives SHA256 from JSON-encoded `[provider.rawValue, accessToken]`. It does not trust claimed fingerprint metadata. The four existing Synthetic/V2EX/XKiro/ZenMux clients retain their published provider-newline-Key format, still recomputed from actual Key. Gateway, region, IBM, xAI, Volcengine and Claude dedicated branches stay ahead of this default. Generic web-v1 fingerprinting only applies to session credentials, so stale unrelated web metadata cannot suppress API Key identity. Non-API session/OAuth fallback remains unchanged; no login/notification policy or storage format is migrated.

Added regressions in the already-registered QuotaMonitorTests file cover metadata-free legacy envelopes, changed Keys, malicious old fingerprint/unrelated web metadata, fixed fingerprint compatibility, dedicated web/gateway/region/composite priority, changed-Key failed refresh plus stale cloud rejection, and same-Key failed refresh retaining its correct snapshot. Root runs the actual target XCTest/build; this branch only performed the red/green offline Swift6 probe, parse and diff checks.

Boundary at this commit: MiniMax China still stores/passes its raw non-envelope Key. This getter repair cannot affect that raw path. It is being assessed independently, and must not be represented as fixed by this change.
