# Qoder 国际版与 DeepSeek 钱包接入访谈

状态：用户已确认设计、A 原型和 5 张工单的拆分；自动化实现与模拟器检查已完成，真实账号、通知及实体 Watch 验收仍待执行。2026-09-15 用户回复“可以”，确认 Qoder 设备凭证过期后在 iPhone 重新授权，再同步到 Watch。

## 已确认

- 原型选择 A（沿用账号卡片结构）；提醒配置统一收归“设置 → 服务账号”，首页卡片不增加提醒设置入口。
- 刷新失败沿用现状，仅提示在对应账号卡片内：收起显示警告图标，展开显示失败原因、保留旧数据说明、原采集时间和单账号刷新入口；不展示全局失败横幅。

- Qoder 国际版由 TokenPulse 直接连接，参考 CLIProxyAPIPlus 的接入方式，不通过其管理接口查询。
- DeepSeek 接入官方 API 账户余额：总可用余额、赠送余额、充值余额和余额是否足够调用 API 的状态；币种分别展示。
- 本次不包含充值操作、账单和消费历史。
- 两个提供商均覆盖 iPhone、Apple Watch、小组件，支持多账号、关注和排序。
- DeepSeek 每个账号选择一个主要币种，作用于钱包概览、小组件和低余额提醒；仅从 API 实际返回的币种中选择，详情保留全部币种。直接使用 API 返回的金额，不做汇率换算。
- DeepSeek 低余额提醒默认开启，默认阈值为 CNY 10 元、USD 2 美元，允许修改。（Q9 推荐方案已获确认。）
- 低余额提醒首次查询已低于阈值也触发；持续低余额只提醒一次，成功查询确认余额高于阈值后再次跌至阈值才重新提醒。离线或查询失败不触发新提醒。（Q7 按推荐方案理解。）
- DeepSeek 返回 `is_available=false` 时提醒余额不足、无法调用 API，与同次低余额提醒合并；持续不可用只提醒一次，查询确认恢复可用后重新允许触发。
- 产品统一使用“服务账号”，可承载套餐额度或 API 钱包余额。
- Qoder 个人额度与组织资源包均需展示，分别展示，不合并计算。
- 登录与同步方案已确认：Qoder 在 iPhone 浏览器授权，DeepSeek 输入 API Key；沿用现有安全凭证同步，Watch 使用同步凭证独立查询。
- Qoder 不承诺自动续期；凭证过期后在 iPhone 重新授权，安全同步新凭证后恢复 Watch 查询。

## 最终确认摘要中的补充规则

- Qoder 个人额度与组织资源包在应用内分别展示；小组件空间不足时由用户选择展示项。
- Qoder 各额度项有有效比例时沿用现有额度告警；缺少比例或总量时不伪造百分比。`expiresAt` 在含义核实前只作为到期时间，不触发周期重置提醒。
- DeepSeek 按币种展示总可用余额，详情展示赠送与充值余额；没有使用百分比和周期重置提醒。所选币种未返回时显示未提供，不填零或自动换币种。
- 查询失败保留最后成功数据并标明时间与失败状态，不根据旧数据触发新余额告警。刷新时机和跨设备通知策略沿用现有规则。
- 先验证 Qoder 真实授权、查询、过期重新授权及 Watch 独立刷新；失败时报告具体障碍，不将模拟响应测试通过视为真实接入成功。

## 验收范围

- 两个提供商的多账号隔离、凭证同步、iPhone 和 Watch 独立查询，以及小组件展示。
- Qoder 个人与组织额度分别显示，缺失字段和到期时间不被误判。
- DeepSeek 币种选择、金额及余额明细准确展示；低余额首次触发、持续去重、恢复后再次触发，以及不可调用提醒合并。
- 离线、凭证失效和查询失败保留可辨认的旧数据，不发出虚假的新额度提醒。
- 完整实现后核对既有提供商行为，保留当前工作区中已有的无关改动。

## 源码核对事实

- 指定 Qoder 提交仅将已有额度快照暴露到管理接口；同版本认证源码采用浏览器设备授权与轮询。额度来源为 `/api/v2/quota/usage`。
- 实现阶段核验更正：认证辅助类虽然有刷新方法，但 `qoder_executor.go` 的实际 Refresh 路径注明设备 `dt-` token 调用该接口返回 403，因而禁用自动刷新。不能将辅助方法存在视为设备凭证可续期。
- 源码支持不等于 iPhone 或 Watch 实测可用；真实账号与设备验证仍待执行。
