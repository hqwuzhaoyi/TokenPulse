## 执行原则

- 当前项目没有应用代码，不需要预先重构。首张任务建立最小可运行产品，不单独拆空壳工程、数据库层、接口层或 UI 层任务。
- 每张任务都交付可从用户入口操作并验证的行为。先走通 MiniMax 国内版，再逐家加入服务，保留已有可运行产品。
- 01—06 使用最小验证界面。所有提供商的登录、查询、凭证续期、多账号隔离和 Watch 独立查询验证完成后，才进入完整产品体验开发；该门槛来自已确认的接入优先决定。
- 所有任务沿用应用层行为测试边界；真实账号登录、设备断联与系统同步需要实机证据，不能以模拟响应代替。真实验证尚未执行时不得标完成，也不得无说明标为有意延期。
- 每个实现任务运行实际选定工具链支持的构建和相关行为检查并记录命令；当前尚无工具链，不编造现有测试命令。
- 开发环境、最低系统版本、签名和实机条件在首次相关任务中检查。缺少用户账号授权或设备能力时报告具体障碍，不把接入失败静默改成 Mac 代查。
- 正式任务建议本地发布在 `openspec/changes/ios-watch-quota-monitor/tickets/`，另写依赖顺序索引；采用目录组织不表示已经配置或运行 OpenSpec 工作流。

## 01 — iPhone 独立查询 MiniMax 国内版套餐额度

**Blocked by:** 无。

交付：用户在最小 iPhone 界面配置 MiniMax 国内版 Coding Plan Key，独立查询套餐额度，分别查看服务实际返回的额度窗口。这张任务包含使该路径可运行所需的最小工程和安全本地存储。

验收要点：

- 真机配置可用订阅 Key 后取得真实额度，确认使用套餐额度而非普通 API 余额；关闭应用再打开仍可本地使用。
- 同一提供商至少两个订阅账号相互隔离；支持前台及手动刷新，显示实际指标和采集时间。
- 查询失败保留上次成功数据，缺失指标显示“未提供”；未开启 iCloud 时仍能使用。
- 可用 Key 与失效 Key 的状态能够区分；账号凭证不进入日志或测试夹具。
- 应用层行为验证覆盖账号隔离、成功查询及失败保留状态，记录构建和真实查询证据。

## 02 — MiniMax 账号同步后在 Watch 独立刷新

**Blocked by:** 01。

交付：iPhone 配置的 MiniMax 账号及凭证通过安全同步到达 Watch，Watch 在手机不在线时可直接查询。保持最小账号和窗口界面，不开展完整表盘式分页设计。

验收要点：

- 验证两端签名和系统能力，选择可支持安全凭证同步的最小实现，并记录设备与版本约束。
- 同步至少两个账号，Watch 使用各自凭证获取各自窗口，手机断开或关闭后仍能手动刷新。
- 新配置尚未到达时明确提示；已经获得凭证的 Watch 在同步暂不可用时仍可直连提供商。
- 在受控恢复场景验证账号与凭证可恢复，不将原 Mac 绑定加密文件用作同步方案。
- 同步传输时间不替代采集时间；显示实际刷新状态，保存实机证据。

## 03 — Claude 多账号登录与双端独立刷新

**Blocked by:** 02。

交付：通过最小 iPhone 登录入口配置 Claude 订阅账号，将可用凭证安全提供给 Watch，两端均能独立查询各窗口。

验收要点：

- 在 iPhone 完成真实登录及额度查询，验证移动端回调路径，不依赖 Mac Keychain 或 CLI。
- 至少两个账号独立配置和查询，凭证与窗口不交叉。
- 手机不可用时 Watch 能直接查询；验证凭证续期，以及两端轮换令牌时是否会导致另一端失效。
- 真实指标、缺失指标和失败状态符合统一行为；与已有 MiniMax 功能共存。
- 提供登录、查询、续期和双端使用证据；若移动端不可行，报告障碍并等待用户决定，不伪造完成。

## 04 — Codex 多账号登录与双端独立刷新

**Blocked by:** 02。

交付：从 iPhone 完成 Codex 账号授权，两端直接查询订阅额度及窗口，不运行 Mac CLI。

验收要点：

- 实机验证设备码或实际可行授权流程、非公开额度查询契约及凭证续期。
- 至少两个账号数据和凭证隔离，Watch 在 iPhone 不在线时仍能查询。
- 验证双端续期不会使另一端凭证失效；失败必须成为明确的接入验证结论。
- 实际缺失字段及请求失败不伪造数值，提供脱敏契约验证与实机证据。
- 不破坏此前已可运行的服务。

## 05 — Z.ai Coding Plan 多账号双端查询

**Blocked by:** 02。

交付：在 iPhone 配置 Z.ai 国际 Coding Plan 账号凭证，手机和 Watch 分别查询套餐额度。

验收要点：

- 用真实国际服务订阅凭证查询套餐额度，不混入国内 BigModel 或普通按量余额。
- 至少两个账号在两端保持隔离；Watch 在手机不在线时独立刷新。
- 验证凭证持久使用及失效后的状态；不虚构静态 Key 的 OAuth 续期流程。
- 非公开响应契约的有效指标、缺失字段及失败展示具有脱敏验证和实机证据。
- 不破坏此前已可运行的服务。

## 06 — SuperGrok 多账号登录与双端独立刷新

**Blocked by:** 02。

交付：在 iPhone 授权 SuperGrok 订阅账号，手机和 Watch 独立获取服务返回的额度信息。

验收要点：

- 验证真实账号授权、查询和续期，确认结果对应 SuperGrok，而非 Cursor Grok Bot 权益或无关 API 余额。
- 至少两个账号隔离；Watch 在 iPhone 不在线时查询；双端凭证续期行为得到验证。
- 额度窗口和重置数据按实际接口能力表达，缺失字段显示“未提供”。
- 提供外部契约检查和真实设备证据，不将参考项目存在登录代码视为已接入。
- 不破坏此前已可运行的服务。

## 07 — iPhone 完整账号列表、关注配置与同步恢复

**Blocked by:** 03、04、05、06（传递依赖包含 01、02）。

交付：五家接入验证完成后，将最小验证入口扩展为可日常使用的 iPhone 多账号列表；用户选择并排序关注账号，设置和数据可同步及恢复。

验收要点：

- 五家服务的账号在列表中正确区分，分别显示多个窗口的比例、剩余额度、重置时间及采集状态。
- 关注选择和顺序可以持久化、同步并恢复；数据、设置与可迁移凭证的换机恢复一起验证。
- 打开应用、手动刷新及系统允许的后台刷新均进入同一可观察行为路径；不以固定后台间隔作为验收承诺。
- 失败和离线保留旧数据；过预计重置时间进入“待更新”，不推断额度恢复。
- iCloud 未开启时本地配置和查询正常；账号之间和同步到达的数据不混淆。

## 08 — Watch 表盘式账号分页与独立刷新体验

**Blocked by:** 07。

交付：Watch 按已同步的关注顺序展示表盘式页面，每页一个账号，页内分别展示多个窗口，左右滑动切换。

验收要点：

- 关注顺序与 iPhone 一致，同一个账号的窗口分别可读，没有合并成总额度。
- 手机不在线时前台和手动刷新仍可用，并接入系统允许的后台刷新机会。
- 新配置未同步、凭证不可用、查询失败和旧数据均有可理解的状态。
- 在实际目标屏幕检查多窗口可读性和分页交互，确认不静默缩减账号或窗口范围。

## 09 — 双端按窗口额度告警

**Blocked by:** 07。

交付：用户在 iPhone 按账号调整额度告警阈值和开关，两端成功刷新后都能判断并发出告警。Watch 提醒可在已有最小界面基础上验证，不依赖 08 的分页布局完成。

验收要点：

- 默认 80%、95%、100%，按账号保存并同步设置，默认开启；关注列表不限制提醒范围。
- 首次查询已超限也告警；70% 到 98% 只发 95% 档，并将 80% 标为已提醒。
- 同窗口周期每档只提醒一次，新周期重新允许；多个窗口同次触发合并为一条账号通知并列明窗口。
- 两端独立刷新时均可通知；已提醒记录同步后减少重复，离线时允许跨设备重复。
- 仅以新查询结果判断新的额度告警，不因缓存重读、请求失败或过预计重置时间制造告警。
- 自动化验证关键阈值行为，并验证真实系统通知及关闭后不再通知的行为。

## 10 — 双端预计重置与确认重置提醒

**Blocked by:** 09。

交付：在既有账号提醒设置与通知路径上加入独立的重置提醒开关；已知时间预排提醒，未知时间仅在查询确认后提醒。

验收要点：

- 重置提醒默认开启，与额度告警开关互不影响，设置可同步。
- 已知时间到达时提示“预计已重置”；应用未运行时验证系统通知，旧数据显示待更新，不伪装恢复。
- 后续查询确认只更新数据，不重复发出同次重置提醒；没有明确时间时不猜测调度，只在查询确认后提醒。
- 提供商重置时间改变时更新通知安排，关闭开关后取消相应安排。
- 多窗口独立判断，复用账号通知合并和跨设备允许重复的已确认规则；记录实机与可控时间行为验证。

## 11 — iPhone 主屏幕与锁屏小组件

**Blocked by:** 07。

交付：用户添加 iPhone 主屏幕和锁屏小组件，指定账号；小尺寸选择一个窗口，大尺寸分别显示多个窗口。

验收要点：

- 两个系统入口均可添加和配置，账号选择正确持久化，组件显示对应数据。
- 小尺寸显示指定窗口，大尺寸分别显示多个窗口，不合并额度；进入应用可查看完整信息。
- 新旧数据与主应用一致，失败或过重置时间后不会显示虚假的实时额度或恢复状态。
- 验证实际目标设备的布局和系统刷新行为，不承诺组件持续实时更新；凭证不暴露在显示内容中。

## 12 — Watch 表盘复杂功能与智能叠放小组件

**Blocked by:** 08。

交付：用户在 Watch 表盘和智能叠放添加账号额度组件，按空间选择单窗口或分别展示多个窗口。

验收要点：

- 表盘复杂功能和智能叠放两个入口均能配置指定账号；小尺寸指定窗口，大尺寸分别显示多窗口。
- 点击能进入相关账号信息，实际设备上的信息可读，窗口身份明确。
- 手机不在线时，Watch 独立刷新取得的数据能更新本地显示来源；组件更新时间受系统调度约束。
- 组件与应用内采集时间和过期状态一致，不把旧值或预计重置误标为实时结果。
