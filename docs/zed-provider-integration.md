# Zed web session, edit predictions and spend budget

The add/reauthorize flow uses an account-owned ephemeral WebKit container, opening the documented dashboard at `https://dashboard.zed.dev/`. The static profile also permits zed.dev/cloud.zed.dev after sign-in. Only `zed.session` from those exact service hosts or their Zed parent domain, applicable to `/frontend/billing/usage`, unexpired and bound to provider/origin/local UUID, is saved in the common secure credential flow. Editor Keychain/internet-password credentials, Safari and other apps are not read.

Phone and Watch independently query `GET https://cloud.zed.dev/frontend/billing/usage` using restricted Cookie + JSON Accept; automatic Cookie and local-cache reuse are disabled and redirects refused. Session mismatch/expiry/tampering fails before a request, HTTP401/403 requires reauthorization. Common UUID lifecycle supplies multiple accounts, local operation without iCloud, restore, credential replacement, deletion and synchronized tombstones.

The private frontend shape is fixed to [Pulse397c8fc4 Zed implementation](https://github.com/qunqin24/Pulse/blob/397c8fc4f1bd52180a452d2f3f0c099def97cf69/Sources/Pulse/Providers/Profiled/ZedUsageService.swift) and [notes](https://github.com/qunqin24/Pulse/blob/397c8fc4f1bd52180a452d2f3f0c099def97cf69/Docs/providers/zed.md), derived from CodexBar. Official [billing](https://github.com/zed-industries/zed/blob/9dd6993e2e6e26baaf0fdfcb152cb823dba1135d/docs/src/account/billing.md) and [plan/spend-limit definitions](https://github.com/zed-industries/zed/blob/9dd6993e2e6e26baaf0fdfcb152cb823dba1135d/docs/src/account/plans-and-pricing.md) were checked at `9dd6993e2e6e26baaf0fdfcb152cb823dba1135d`. They confirm the dashboard, limited vs unlimited predictions, dollar token usage, monthly billing and zero spending budgets. They do not verify this private Cookie name/endpoint for a real account today.

`current_usage.edit_predictions` is a separate count window. Numeric `limit` and `{limited:n}` give a denominator when positive; only explicit `"unlimited"` displays infinity. Null/missing limits retain reported use without pretending an unknown limit is zero or infinite. `token_spend.spend_in_cents/limit_in_cents` is a separate USD spend budget; Decimal division by100 and subtraction are checked, not a wallet balance. Null limit retains spend-only, positive cap produces a usage rate, overspend remains real and exhausted. A zero cap is preserved as a zero configured budget without a fabricated 0/0 percentage or an unlimited claim. Static status explains unset/zero budget without hiding prediction/spend data.

No reset date appears in the chosen web reply. The code does not borrow dates from the editor route, infer subscription day, or manufacture next month. Threshold alerts only use trustworthy denominators; unlimited, spent-only and zero-denominator rows do not produce a fake ratio. No low-wallet or manual-reset controls; reset toggle remains hidden. The demo shows unlimited predictions and a distinct numeric USD budget in isolated local storage.

Six new regression methods cover cookie/account/origin/query contract, count vs USD units, explicit unlimited/unset/zero semantics, invalid Bool/negative/HTML/shape, alert/no-reset/widget/coding/demo and isolated account restore/rekey/delete/failure retention. Sources/tests parse and PBX lint passed, aggregate compile/XCTest delegated to root. No worker Xcode/simulator run.

Icon is the explicitly non-brand generic extension mark used by pinned Pulse (Sources/Pulse/Resources/extension.svg), Apache2, black 24x24 template/vector; provenance and full license in notices. Official Zed app assets are primarily GPL3 rather than an appropriate source for this integration's asset bundle.

Current close criterion is implemented integration plus icon existence; no real-account/device gate. Browser sign-in behavior, Cookie acceptance, session lifetime, physical Watch/iCloud and rendered widget appearance remain unmeasured observations, not claims of production validation.
