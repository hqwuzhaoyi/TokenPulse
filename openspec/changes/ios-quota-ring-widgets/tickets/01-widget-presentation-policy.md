# 建立按组件尺寸选择账号与额度的展示策略

**Status:** `complete`

## What to build

建立单一的 Widget 展示策略，让时间线条目根据组件尺寸和用户配置提供正确数量的账号及额度窗口。小组件和 accessory family 最多选择一个账号；中组件最多选择两个；大组件最多选择四个。账号来自主屏幕已配置列表，按选择顺序展示并按首次出现去重。删除旧单账号参数和自动截取列表前 2/4 个的路径，不增加兼容层。

额度规则必须与主应用的套餐语义一致：MiniMax 主屏幕显示 5 小时额度；GLM 分别显示周额度和 5 小时额度；Codex 根据实际套餐分别显示适用的 5 小时与周额度；SuperGrok 显示其真实额度窗口。不同额度窗口保持独立，不能合并百分比、状态或重置时间。

## Acceptance criteria

- [x] 小、accessory、中、大组件分别接受最多 1、1、2、4 个已配置账号；验证：运行 Widget 展示策略测试，覆盖空选择、乱序选择、超量选择和重复选择。
- [x] 所有尺寸严格使用账号集合配置的顺序，不自动补入未选择账号；验证：运行时间线选择测试并在系统大组件编辑页添加两个不同账号。
- [x] MiniMax、GLM、Codex、SuperGrok 的可见额度窗口符合已确认规则，缺失窗口保持“未提供”，不同周期不合并；验证：运行四个渠道的展示矩阵测试。
- [x] 新鲜、待更新、刷新失败、无限额度和缺失百分比均保留准确状态；验证：运行 Widget 状态测试并断言没有把未知值渲染为 0%。
- [x] 全量 XCTest 通过，且没有为旧单账号 Entry 保留兼容分支；验证：运行项目全量测试并检查废弃类型或调用已清除。
