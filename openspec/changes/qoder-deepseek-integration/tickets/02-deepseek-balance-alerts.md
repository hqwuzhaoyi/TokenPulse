# DeepSeek 低余额提醒

**Status:** `ready-for-agent`

## What to build

用户在“设置 → 服务账号 → DeepSeek”管理低余额提醒。提醒默认开启，继承应用通知总开关；所选主要币种决定金额阈值，默认 CNY 10 元或 USD 2 美元，允许修改。每次成功查询后判断低余额与 API 不可用状态，并通过现有通知与同步机制投递和记录。

## Acceptance criteria

- [x] 提醒开关、币种和阈值只在设置中管理，阈值为非负十进制金额，保存后重启保留；验证：设置操作、输入校验和持久化测试。
- [x] 总可用余额小于或等于所选币种阈值时触发，首次查询已低于阈值也提醒；其他币种不触发该账号低余额提醒；验证：高于、等于、低于阈值及双币种测试。
- [x] 持续低余额只通知一次，成功查询确认高于阈值后再次跌至阈值才重新通知；验证：首次低余额 → 持续低余额 → 恢复 → 再次低余额状态序列。
- [x] `is_available=false` 独立触发不可调用提醒，即使币种缺失或余额未达到阈值；与同次低余额提醒合并。持续不可用不重复，恢复可用后重新允许触发；验证：合并、空余额数组和恢复测试。
- [x] 关闭账号提醒或应用通知总开关不投递通知；失败、离线旧数据、仅修改设置均不冒充新的成功采集触发提醒；验证：开关和旧数据测试。
- [x] 提醒记录重启后保留，设备同步时较新的观察优先，旧状态不能错误重新启用已触发提醒；沿用既有跨端策略，不承诺完全消除双端同时提醒；验证：持久化、乱序合并和双端状态测试。
- [ ] 钱包不进入套餐百分比告警与重置提醒，既有提供商通知行为无回归；验证：完整通知 XCTest，并在获通知权限的设备上实际触发一次低余额通知。→ XCTest 已通过（`WalletTests.testWalletWindowsNeverEnterQuotaPercentageOrResetReminders` 等）；**真机通知权限下实际投递未执行，保持未勾选**。
